# AArch64 E5/E6 spike: booting the SD image's system under qemu-system-aarch64

AArch64 plan §6 item 7, experiments E5 (does `-M virt` boot it, and how fast
is boot to login?) and E6 (`nixos-generate-config` on non-EFI AArch64).
User decision U5: the Pi firmware/U-Boot chain need not be tested, so this
uses a direct kernel boot.

- **Artifact:** E4's SD image (0.15.0),
  `/nix/store/24ywhnjh…-nixos-image-sd-card-26.05.20261015.26f4107-aarch64-linux.img.zst`
  (1.6 GiB compressed, 3.96 GiB raw). Its system closure is
  `/nix/store/r029j6da…-nixos-system-nixos-sd-card-26.05.20261015.26f4107`.
  Its `kernel-params` are byte-identical to the user's CM4 `/proc/cmdline`:
  R-P2 holds on the built artifact.
- **Host:** `qemu-system-arm` 8.2.2, installed by hand on 2026-10-19 and not
  yet in `DEV_APT_PACKAGES`.
- **QEMU:** `-M virt -cpu cortex-a72 -smp 2 -m 2048`, `-kernel/-initrd` from
  the closure, `-append "<kernel-params> init=<closure>/init"`, the SD image as
  a writable virtio disk, an empty 4G virtio target, and `-serial stdio` (the
  PL011, seen as `ttyAMA0` in the guest).
- Script: `notes/2026-10-19T031843Z-aarch64-e5-spike/spike.py`.

## run1 (QEMU from 2026-10-19 02:41:51Z, login timeout 300 s, the default)

- The kernel booted: `Machine model: linux,dummy-virt`, `ttyAMA0 … PL011`, and
  root from the SD image. systemd reached its targets, created the
  `serial-getty` slice and logged "Expecting device /dev/ttyAMA0…". pre-nixos
  printed its version banner.
- No `login:` arrived within 300 s, by which point the guest clock had
  reached only about 123 s.

## run2 (02:47:33Z to 03:17:38Z, login timeout 1800 s, clean disks)

- Again **no login prompt in 30 minutes**. pre-nixos ran: it broadcast
  `LAN IPv4 address unavailable (preferred interface "lan" not found)`.
- Kernel messages stop at about 120 s. `systemd-journald` restarted at 75 s.
- Hypotheses, unverified:
  - **H1:** nothing is wrong except that `/dev/console` is `tty0` (the last
    `console=`), so systemd's status output goes to VGA, not serial, and we
    cannot see why the getty is missing.
  - **H2:** `dev-ttyAMA0.device` never became ready, and systemd's 90 s
    device timeout expired under slow emulation, so the getty's dependency
    failed.
  - **H3:** a getty runs but its output does not reach the serial port.
- Separately: `lan` was not found. That is the NIC rename under `virt`, a
  separate question (reqs §2.6).

## run3 (diagnosis only: `console=ttyAMA0,115200n8` appended, making serial primary)

One variable changed, observability, to tell H1, H2 and H3 apart.

Result (03:18:29Z to 03:43:35Z): **H2 confirmed**. With serial as the primary
console, systemd's status lines show:

```
[  OK  ] Started Getty on tty1.
[ TIME ] Timed out waiting for device /dev/ttyAMA0.
[DEPEND] Dependency failed for Serial Getty on ttyAMA0.
[FAILED] Failed to start Pre-NixOS setup.
[  OK  ] Reached target Multi-User System.
```

- The serial getty's device job uses systemd's default 90 s device timeout,
  and udev coldplug under TCG emulation finished later than that. So there
  is no serial login, while the VGA getty (tty1) started.
- Real CM4 hardware boots far faster, so this is a VM-test artefact. Fix for
  the VM test only, on the direct-kernel-boot command line:
  `systemd.default_device_timeout_sec=900`.
- **New product finding: pre-nixos.service failed on AArch64.** Its cause
  is to be read from its journal in run4.
