## run1 (2026-10-19 00:25:51Z to 00:32:50Z): a planner bug

- Disks: vda (virtio, 4G), and sda and sdb (`scsi-hd` rotation 7200, 2G).
  Because of U2, all three are HDDs.
- Result: `STATE=applied DETAIL=auto-applied`, but VGs were `large` (vda1) and
  `swap` (md0). **There was no `main` and no `slash`**, and `large/data`
  was mounted on `/mnt/data`.
- Filed as trbarbour/NixOS-boot-image#313. Root cause, from the code: without
  an SSD, `main` and `swap` both chose the RAID-1 pair, and `swap` took
  precedence. Also, the swap-room check compared bytes with GiB
  (`min_size < 2 * ram_gb`), so it never excluded anything.
- Fix: `main` is chosen first and its bucket is left out of the swap
  candidates; the comparison is now in bytes; a postcondition asserts that
  `main/slash` exists. New tests are in `tests/test_planner_hdd_only.py`
  (3 of 4 failed on the old code).
- The existing `test_multiple_hdd_buckets_named_separately` expected the
  buggy plan, with no `slash`. It was corrected to reqs §2.4.

## U4 decided: no write-intent bitmap (user, 2026-10-19)

- The user's rule: "No write-intent bitmap, unless it can be external, on
  SSD. Can the latter case be added later on? If so, the boot image does not
  need to be concerned with it."
- **External bitmaps are gone.** mdadm 4.4's `CHANGELOG.md` says "Remove
  custom bitmap file support", and `mdadm.c` now refuses: "Custom
  write-intent bitmap file option is not supported". So an SSD-hosted
  bitmap is impossible with this toolchain.
- **An internal bitmap can be added later.** `Grow.c` handles `BitmapInternal`
  and `BitmapNone` (`mdadm --grow --bitmap=internal|none`).
- Policy: arrays are created with **no bitmap**. Recorded as reqs §2.2
  [R-R1].
- Enforcement, design debate:
  - **(a) Chosen:** patch disko's `mdadm --create` to add `--bitmap=none`
    in the flake's disko overlay, using `substituteInPlace --replace-fail`,
    so an upstream change of that line fails the build.
    - mdadm then asks no bitmap question, so disko's `echo 'y'` again
      answers "Continue creating array?", as on 25.05. This also removes
      the prompt-order risk.
    - Experiment: the patched disko's generated RAID script contains
      `echo 'y' | mdadm --create --bitmap=none "/dev/md/md0"`.
  - **(b) Rejected:** removing the bitmap afterwards with `--grow`. The `y`
    would still answer the wrong question.
- Tests:
  - `tests/vm/test_raid_provisioning.py` now asserts that there is no
    "Intent Bitmap" in `mdadm --detail`, which mdadm prints only when a
    bitmap exists (`Detail.c`), and no `bitmap:` line in `/proc/mdstat`.
  - `tests/vm/test_disko_offline_closure.py` gains a `raid1` layout: the
    script must contain `mdadm --create` with `--bitmap=none`, and must
    build offline.
