- **Run:** by the user on their CM4 (same hardware as attempt 1), 2026-10-22. The install finished at 15:50:32Z.
- **Image:** 0.21.0, built in 8 minutes; the NVMe was wiped first.
- **Log:** `2026-10-22T154500Z-cm4-item10-attempt2-serial.txt` (serial, from power-on through the installed system's `Starting kernel ...`).
- **Tickets:**
  - trbarbour/NixOS-boot-image#323: the installed initrd cannot reach the NVMe root;
  - trbarbour/NixOS-boot-image#324: sshd was not started during the install.

## Failures

1. **Serial output stops at `Starting kernel ...`, and there was no DHCP lease** → #323.
   - The installed initrd has no `pcie-brcmstb`: the Pi's PCIe bridge driver is a module in this kernel.
     - The SD installer has it only through `all-hardware.nix`.
     - `nixos-generate-config` cannot detect a platform bridge; it adds `nvme` only.
   - So the NVMe, and with it the LVM root, never appears in the initrd. Stage 2 (networkd, sshd, the serial getty) is never reached.
   - The serial port shows nothing for two reasons. `loglevel=4` (the SD image uses 7) hides the kernel's info lines. And `console=tty0` is the last console, so systemd's status lines and any emergency shell go to HDMI.
   - **Proved by evaluation and build, not yet on hardware:**
     - the evaluated installed configuration lacks the module;
     - after the fix, the installed AArch64 initrd, built here, contains `pcie-brcmstb.ko.xz`, `nvme.ko.xz` and `nvme-core.ko.xz`;
     - the flake check `installed-rpi-initrd-storage` fails before the fix and passes after it.
2. **No SSH on the installer while it installed** (the user checked port 22 with telnet; ping worked) → #324.
   - `sshd` is ordered `After=pre-nixos.service`. That oneshot unit runs the whole auto-install, so the start queued by `secure_ssh` waited until the install ended, and then the machine rebooted.
   - Attempt 1 had SSH only because its install failed and `pre-nixos` exited.
   - The repo had already observed the mechanism (`docs/work-notes/2025-10-19T00-12-43Z-sshd-pre-nixos-verification.md`: "sshd.service queued in start waiting while pre-nixos.service continues running").
   - The flake check `installer-sshd-start` fails before the fix and passes after it.

**Regression check:** the x86 VM test `tests/vm/test_pre_nixos_vm.py`, which includes the SSH login, passed 3/3 at 0.21.1 (2026-10-23 01:03Z, 11 min 26 s).

## Other anomalies (recorded on the task queue)

- **Wrong clock at the start of the install:** `Starting automatic NixOS installation at 2026-03-17 19:56:48Z`. The clock was still at the image's built-in epoch, because timesyncd had not synced yet. Task queue item 24.
- **No version in the installed system's label:** `26.05pre-git` instead of `26.05.20261015.26f4107`. The installed nixpkgs (the channel `nixos-install` copies) seems to lack its version files. Task queue item 25.
- **Installed U-Boot 2026.10 prints an error:** `ERROR: reserving fdt memory region failed (addr=0 size=1000 flags=4): -17` (-17 is EEXIST, so probably a duplicate reservation, which is harmless). U-Boot 2026.04 on the SD card did not print it. Task queue item 26.
- **Persisting from attempt 1:** undervoltage warnings (item 23) and CMA exhaustion (item 20).

## Next

Build 0.21.1, wipe the NVMe, and repeat the test.

**Open question for the user:** should the installed Pi make the serial port the *primary* console (`console=ttyS0` last)? Then systemd's status lines and any emergency shell would appear on serial. Today the installed system copies the installer's console order, in which HDMI (`tty0`) comes last.
